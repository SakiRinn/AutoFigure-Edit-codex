# AutoFigure-Edit Codex

用户调用本Skill后，由当前Codex Agent执行AutoFigure-Edit主流程，再完成后处理与交付。

> **执行职责**
>
> Agent负责材料准备、进程运行及后处理；Python Provider通过Codex SDK完成模型调用。

主流程的提示模板与阶段算法保持冻结，后处理修改独立工作副本。

## 启动准备

先确定运行主机与仓库位置，再读取该仓库的 `TUTORIAL.md`，按实际环境准备依赖。

**环境核对：**

- 从用户指定路径、当前项目或 `AUTOFIGURE_CODEX_ROOT` 定位仓库。
  - 确认 `autofigure2.py` 和 `codex_bridge.py` 存在，将项目Python路径记为 `PROJECT_PYTHON`。
  - `SKILL_DIR` 使用本次加载的Skill目录，后处理脚本从该目录调用。
- 在执行主机检查项目依赖及 `codex login status`。
  - SDK使用执行主机的登录状态；缺少登录时告知用户在该主机完成登录。
  - 缺少Codex CLI时按教程安装 `@openai/codex@latest`，Python依赖按仓库安装。
- 按已配置的分割后端准备SAM3，核对RMBG权重和所需凭据。
  - 运行命令按需加载本地 `.env`，凭据留在进程环境中。
  - macOS的Cairo配置与远端GPU启动器按教程处理，核实路径存在后使用。

环境确定后，创建本次运行目录，并将其绝对路径记为 `RUN`，供主流程和后处理使用。

### 输入材料

新任务使用独立运行目录。按[生图设计](references/design.md)组织画面，将用户要求与适用风格写入材料。

缺少绘图材料时，补问需要表达的方法或项目路径，再准备输入。

**输入处理：**

- 用户提供方法说明时，整理为 `method.txt`，保留关键步骤与模块关系。
- 用户提供项目代码时，核对入口和数据流，再将实际方法整理为 `method.txt`。
- 用户提供已定稿图片时，使用 `--input_figure_path` 跳过生图，替代方法文本参数。

SDK任务与当前对话隔离。方法文本生图时，`method.txt` 须写明绘图内容和风格。

生图需要参考图时，通过 `--reference_image_path` 传入本地路径；上游会启用参考图输入。

默认采用rich pastel配色，图标使用lineal color或restrained flat特征，也可融合。

结构关系优先用形状示意，图标用于概括对象。将这些要求写入方法文本，并按[生图设计](references/design.md)选择主参考图。

用户指定参考图优先；使用配套参考图时，选择 `lineal_color.png` 或 `restrained_flat.png`。

在方法文本中明确两张配套示例仅参考图标绘制风格；具体造型、配色与字体按当前任务设计，无需对齐示例。

参考图参数用于方法文本生图；图片导入模式以定稿图本身为外观依据。

上游默认将不足4K长边的图片放大；用户要求保留原始像素尺寸时，传入 `--disable_auto_upscale`。

## 执行主流程

由当前Agent执行启动命令并保留进程句柄。材料齐备后持续推进到后处理，不能只给用户一条命令。

启动命令须采用执行主机上的解释器和实际输入路径，分割后端与优化次数按任务配置。

以下示例从仓库根目录启动本地分割，执行一次SVG优化；路径与参数值按本次任务替换。

```bash
.venv/bin/python -u autofigure2.py \
  --provider codex \
  --method_file outputs/run-001/method.txt \
  --output_dir outputs/run-001 \
  --sam_backend local \
  --optimize_iterations 1 \
  > outputs/run-001/run.log 2>&1
```

远端运行时按教程替换Python或启动器路径，输入和产物路径均使用执行主机上的路径。

**参数约定：**

- 保留 `--provider codex`，生图Provider默认跟随；模型请求由SDK自动完成。
- 完整流程默认执行到第5步，只有用户要求阶段性输出时才设置 `--stop_after`。
- 默认使用Codex配置的Agent模型；用户指定模型时通过 `--svg_model` 传入。
- 生图模型由内置工具管理，使用默认 `codex-imagegen`；尺寸与放大行为按教程处理。

进程启动后，以当前进程状态、日志和本次生成的文件判断执行结果。

### 跟进运行

读取 `run.log` 了解当前阶段，并等待同一进程结束；同一输出目录只运行一个进程。

**完成检查：**

- `Codex calling` 表示Provider正在调用SDK，保持原进程运行并继续观察日志。
- 主流程结束后核对退出状态与 `final.svg`，结合日志检查阶段错误。
- 渲染 `final.svg` 并检查结构；仅嵌入整张图片的保底SVG须标为主流程未完成。
- 主流程成功后保留原稿，接着执行后处理，完成PPTX验证后再交付。

Provider在内存中返回模型结果。运行状态通过进程和日志读取，外层Agent只操作输入及生成后的产物。

### 中断处理

进程失败或中断时，先读取日志定位原因；修正运行条件后重新执行命令。

每次模型调用都会重新请求SDK。重跑使用新的输出目录，避免旧产物混入本次完成检查。

**处理约定：**

- 环境或输入错误在已授权范围内修正，保留原始错误便于核对。
- 登录、额度或权限问题需要用户处理时，说明具体阻塞与下一步。
- 同一原因修正后仍失败时停止重跑，报告错误；已完成产物保留供用户检查。

主流程产物可用后，按[可编辑转换](references/postprocess.md)核对SVG，在工作副本修复缺陷并处理编辑单元。

## 后处理

先查看渲染图与SVG树，决定实际编辑单元，再生成 `editable.svg` 与PPTX。\
SVG重建检查、PPTX导出与后处理规则统一见[可编辑转换](references/postprocess.md)。

> **外观一致性**
>
> SVG/PPTX除字体替换与有记录的明确生成缺陷外，须一比一复刻定稿生成图。
>
> 字体按[文本规则](references/postprocess.md#文本)选择，保留文字内容与层级；对象合并保持图形外观。

对象边界由语义决定，先完成裁决，再执行转换。

### 编辑单元

密集小图元应合为用户会整体移动的完整对象。\
文本以完整语义单元为边界，外部标签和面板各自保留编辑身份。

**图形裁决：**

- 同一密集区域内共同表达完整语义的图元合为一个编辑单元，颜色差异不构成拆分依据。
  - 例如，同一片多色散点及其内部连线共同表达样本分布，应整片合并。
- 选定密集区域能用单个复合路径忠实表达时，合为该路径；否则整片转为局部图片。
  - 例如，同色图元可合为复合路径，多色散点可整片保留为局部图片。
- 样本分布的选定区域最终对应一个叶对象，分组不能代替叶对象压缩。

每个图标按结构复杂度逐个裁决，简单图标转整体矢量，复杂图标保留局部位图。\
画布中只放置一个图标实例，禁止展开为大量小对象，也不能用分组代替对象压缩。

文本合并保留原生编辑能力，不通过图片替代文字。

**文本裁决：**

- 同一段落的多行合为一个文本框，标题与正文分别保留。
- 属于标题的限定说明归入同一文本框；同一模块、相邻位置或内容相关不足以跨单元合并。
  - 例如，标题附带的括号限定语仍属于标题，独立正文另设文本框。
- 合并为一个SVG `text`，用 `tspan` 保留位置与混合样式，导出为一个原生PPT文本框。
- 单元内部保留不同字号和粗细；分组或文字栅格化均不满足文本合并。

裁决结果写入显式计划，脚本只负责执行已确定的操作。

### 转换

`merge-plan.json` 记录选中元素及其语义理由。\
转换保持详细源稿，所有后处理均在工作副本上进行，依次完成：

1. 用 `scripts/compact_svg.py` 执行适用计划；脚本不负责选择元素。
2. 超出支持范围时，在运行目录编写专用转换代码，遵守相同约束并检查局部渲染。
3. 对照压缩前后渲染，检查文字、色彩和连接关系，复查已记录缺陷。
4. 用 `scripts/svg_to_pptx.mjs` 和Artifact Tool导出PPTX。

导出时分别处理普通组件、复杂资产与背景层级。

**对象要求：**

- 按 [原生对象选型](references/postprocess.md#原生对象选型) 使用预设形状与连接符；箭头使用原生端点。
  - 自由曲线不等于对应的预设形状，线条加三角形不等于原生连接箭头。
  - 按 [整体图标](references/postprocess.md#整体图标) 逐个选择矢量或位图；每个图标保留单个对象。
- 背景面板保留完整形状，局部色块作为独立对象置于上层，不得因遮挡而挖孔或切碎。
- 底层全画布纯色背景使用PPT页面背景，局部覆盖层保留为独立对象。
- 导出失败须修复具体组件，禁止用整页图片代替。

上游抠图用于简单图标的矢量重建，也可作为复杂图标的交付资产。\
记录每个图标的结构依据与输出类型，禁止将整批图标默认归为复杂图标。

对象结构正确后，还需从最终文件核对外观和编辑行为。

## 交付

渲染最终PPTX，与SVG及定稿生成图按相同画布尺寸叠加对照。\
按字体替换规则检查文字，其余区域核对外观一致性，修复缺失或移位后再交付。

**文件检查：**

- 选定样本分布区域在SVG与PPT中均为一个叶对象；每个图标为一个整体对象，文本单元各为一个文本框。
- 核对完整文字与粗细样式，检查实际PPT对象类型及连接符绑定，移动模块验证箭头跟随。
- 检查PPTX实际文件，确保备注内容为空。
- 提供原始SVG、压缩SVG、PNG和PPTX链接，报告真实压缩数量及局部图片范围。

交付说明须区分已完成的结果和仍待处理的问题。

> **未完成判据**
>
> 全画布栅格、未处理的密集图元或无法运行的必要步骤均须标为未完成。\
> 字体替换与明确缺陷修复之外的外观差异须如实记录，未解决时不宣称一比一复刻。
