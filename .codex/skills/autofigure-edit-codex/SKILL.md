# AutoFigure-Edit Codex

用户调用本Skill后，由当前Codex Agent执行AutoFigure-Edit主流程，再完成后处理与交付。

> **执行职责**
>
> Agent负责材料准备、内置生图和后处理。Python Provider等待图片回传，文本请求继续使用Codex SDK。

主流程的阶段算法保持冻结。英文模板依次放入 `<STYLE>`、`<METHOD>`，有细节要求时再加入 `<DETAIL>`。后处理修改独立工作副本。

## 启动准备

先确定运行主机与仓库位置，再读取该仓库的 `TUTORIAL.md`，按实际环境准备依赖。

**环境核对：**

- 从用户指定路径、当前项目或 `AUTOFIGURE_CODEX_ROOT` 定位仓库。
  - 确认 `autofigure2.py` 和 `codex_bridge.py` 存在，将项目Python路径记为 `PROJECT_PYTHON`。
  - `SKILL_DIR` 使用本次加载的Skill目录，后处理脚本从该目录调用。
- 在执行主机检查项目依赖及 `codex login status`。
  - SDK使用执行主机的登录状态；缺少登录时告知用户在该主机完成登录。
  - 缺少Codex CLI时按教程安装 `@openai/codex@latest`，Python依赖按仓库安装。
- 按已配置的分割后端准备SAM3，核对RMBG权重和所需凭据。
  - 运行命令按需加载本地 `.env`，凭据留在进程环境中。
  - macOS的Cairo配置与远端GPU启动器按教程处理，核实路径存在后使用。

环境确定后，创建本次运行目录，并将其绝对路径记为 `RUN`，供主流程和后处理使用。

### 输入材料

新任务使用独立运行目录，分别准备方法与风格。输入文件均为UTF-8文本，可使用Markdown。首轮默认只使用方法与风格，省略 `detail.txt`，让模型在科学事实和整图风格内自由构图。

三个文件按约束对象分工：

| 文件 | 职责 | 约束对象 |
| --- | --- | --- |
| `method.txt` | 论文方法与科学事实 | 模块含义及真实关系 |
| `style.txt` | 宏观绘制风格 | 整图的配色、字体与视觉语言等共性规则 |
| `detail.txt` | 微观绘图细节 | 指定模块、区域或连接的局部安排 |

**输入处理：**

- 用户提供方法说明时，整理为 `method.txt`，保留方法事实与模块关系。
  - 写明图要解释的问题、实际输入输出、必须出现的模块与准确标签。
  - 保留关键连接的方向及含义；具体端点和走线遵循细节要求，其余由模型安排。
- 用户提供项目代码时，核对入口和数据流，再将实际方法整理为 `method.txt`。
- 用户提供已定稿图片时，使用 `--input_figure_path` 跳过生图。

绘图风格通过独立文件传入，方法文本沿用原版内容职责。

**风格文件：**

- 仓库根目录的 `style.txt` 是默认风格。CLI未传 `--style_file` 时加载该文件。
- 用户有特殊要求时，将默认文件复制到本次运行目录，再修改对应条目。
  - 传入 `--style_file "$RUN/style.txt"`，该文件完整替换默认风格。
  - 消除文件内部冲突，保留用户未覆盖的适用要求。
- 读取本次实际使用的风格文件，确认明确要求已写入；未限定的视觉细节由模型安排。
- 常规绘图无需重新通读 `design.md`，也无需将其规则逐项补入方法文本。

[生图设计](references/design.md)用于维护默认风格。修改默认文件后，须让独立subagent逐条审查覆盖，修正后复核。

### 绘图细节

具体安排使用 `--detail_file "$RUN/detail.txt"` 传入，文件全文进入 `<DETAIL>`。

**内容约定：**

- 最佳实践是首轮不写细节，查看画面后再逐步补充有依据的局部要求。
- 每次保存当前完整要求，保留仍有效的决定，替换过时条目并消除冲突。
- 省略参数或文件内容为空白时，不加入细节区块；项目不自动加载默认细节文件。
- 保留项与改进目标可用Markdown章节区分，程序不解析固定章节或条目格式。

style约束整图的共性规则，detail只约束所指部分。每条细节须明确对应的模块、区域或连接。

**约束关系：**

- 具体安排须保持方法事实；明确的局部覆盖优先于一般风格默认项。
- 未规定的部分按方法与风格安排；不要替用户补出无依据的固定布局。
- 有参考图时，明确风格要求与细节要求均优先于参考图。

### 图中文字

科研图用图形解释机制，文字用于识别对象。输入准备和验收均执行以下要求。

**禁止文字补丁：**

- 禁止给模块名追加括号解释、描述性从句或说明段落来补足图形。
- 将要表达的细节转为形状、连接、运算符或局部展开，保持科学含义。
- 需要长文字才能说明的内容放入图外caption或正文。
- 技术名称和数学记号中的必要括号，以及作为数据展示的查询原文，按内容保留。

整图标题由图外caption承担，图内保留必要识别信息。

**验收要求：**

- 清除自动生成的整图大标题、副标题、总结句和caption式叙述。
- 保留对象短标签、数学符号、数据刻度与简短图例；逐项判断文字用途。
- 检查括号及长标签，发现解释性补丁时要求改用图形表达，再重新验收。
- 提炼候选图细节时，将文字补丁列为待改进项，不继承为应保留的设计。

### 候选图再生成

出现值得继承的候选图且需要继续改进时，Agent应主动提炼 `detail.txt`，写清满意特征与局部改进目标。

先查看实际画面，再逐轮补充细节；首轮保留自由构图空间，不预先编造局部安排。

**提炼要求：**

- 满意部分描述其具体特征；改进部分描述下一版应呈现的目标状态。
- 写清对象、位置和关系，避免仅写沿用上一版或修改此处等依赖旧图的指代。
- 方法修订写入 `method.txt`，影响整图的宏观风格调整写入 `style.txt`，仅影响所指部分的微观安排写入 `detail.txt`。
- 每轮传入完整细节文件，按本轮有效要求重新生成；按需迭代，不强制执行多轮。

上一版候选图供Agent观察，不自动作为生图图片输入。用户明确指定的风格参考图继续按参考图规则传入。

查看实际结果后，再判断保留要求与改进目标是否实现。

**生成后验收：**

- 查看实际生成图，核对方法、实际风格及细节要求，逐项检查保留项与改进目标。
- 在运行目录保存检查记录，注明图中位置、结果及未解决问题。
- 发现问题时记录目标结果，修改所属输入文件并复核相关内容。
- 字体外观按风格检查；精确字体与可用性按后处理文本规则核验。

默认风格包含rich pastel配色、字体与图标要求，支持适用的立体结构和自然圆形。

**参考图使用：**

- 仅在用户明确指定生图参考图时，通过 `--reference_image_path` 传入一张本地图片。
- 参考图提供视觉风格；方法决定结构与连接，组件数量及布局按方法安排。
- 风格与细节文件的明确要求优先于参考图，其余视觉细节可借鉴参考图。
- 配套 `lineal_color.png` 和 `restrained_flat.png` 仅供Agent理解图标，不作为生图输入。

上游默认将不足4K长边的图片放大；用户要求保留原始像素尺寸时，传入 `--disable_auto_upscale`。

## 执行主流程

由当前Agent执行启动命令并保留进程句柄。启动前读取 [生图交接](references/imagegen.md)，确认本会话内置image-gen可用。

原程序在生图调用内等待。Agent须先查看生成图，按方法、实际风格及细节要求验收并定稿，再回传图片。

未通过验收的图片禁止回传成功响应，也不能进入分割或SVG重建。定稿回传后继续跟进同一进程至后处理。

启动命令须采用执行主机上的解释器和实际输入路径，分割后端与优化次数按任务配置。

以下示例从仓库根目录启动本地分割，执行一次SVG优化；路径与参数值按本次任务替换。

```bash
export AUTOFIGURE_IMAGE_REQUEST_DIR="$PWD/outputs/run-001/.imagegen"
.venv/bin/python -u autofigure2.py \
  --provider codex \
  --method_file outputs/run-001/method.txt \
  --output_dir outputs/run-001 \
  --sam_backend local \
  --optimize_iterations 1 \
  > outputs/run-001/run.log 2>&1
```

远端运行时按教程替换Python或启动器路径，输入和产物路径均使用执行主机上的路径。

**参数约定：**

- 保留 `--provider codex`，生图Provider默认跟随；Agent回传生图结果，SDK自动完成文本请求。
- 完整流程默认执行到第5步，只有用户要求阶段性输出时才设置 `--stop_after`。
- 默认使用Codex配置的Agent模型；用户指定模型时通过 `--svg_model` 传入。
- 生图使用默认 `codex-imagegen`；模型与思考强度受内置工具接口约束，尺寸与放大行为按教程处理。

进程启动后，以当前进程状态、日志和本次生成的文件判断执行结果。

### 跟进运行

读取 `run.log` 了解当前阶段；同一输出目录只运行一个进程。

出现 `Codex image request:` 后，按 [生图交接](references/imagegen.md) 处理该请求，再等待同一进程继续。

**完成检查：**

- `Codex calling text` 表示SDK文本请求；`Codex image request:` 表示等待生图与验收，定稿后回传。
- 主流程结束后核对退出状态与 `final.svg`，结合日志检查阶段错误。
- 渲染 `final.svg` 并检查结构；仅嵌入整张图片的保底SVG须标为主流程未完成。
- 主流程成功后保留原稿，接着执行后处理，完成PPTX验证后再交付。

Provider将回传图片读为PIL对象，文本结果通过SDK返回。Agent按请求原文调用内置工具，原程序继续保存产物。

### 中断处理

进程失败或中断时，先读取日志定位原因；修正运行条件后重新执行命令。

每次生图调用创建独立交接目录，文本调用创建SDK任务。重跑使用新的输出目录，避免旧产物混入完成检查。

**处理约定：**

- 环境或输入错误在已授权范围内修正，保留原始错误便于核对。
- 登录、额度或权限问题需要用户处理时，说明具体阻塞与下一步。
- 同一原因修正后仍失败时停止重跑，报告错误；已完成产物保留供用户检查。

主流程产物可用后，按 [可编辑转换](references/postprocess.md) 核对SVG，在工作副本修复缺陷并处理编辑单元。

## 后处理

先查看渲染图与SVG树，决定实际编辑单元，再生成 `editable.svg` 与PPTX。

SVG重建检查及后处理规则统一见 [可编辑转换](references/postprocess.md)，其中包含PPTX导出要求。

> **外观一致性**
>
> SVG/PPTX除字体替换与有记录的明确生成缺陷外，须一比一复刻定稿生成图。
>
> 字体按 [文本规则](references/postprocess.md#文本) 选择，保留文字内容与层级；对象合并保持图形外观。

对象边界由语义决定，先完成裁决，再执行转换。

### 编辑单元

密集小图元应合为用户会整体移动的完整对象。

文本以完整语义单元为边界，外部标签和面板各自保留编辑身份。

**图形裁决：**

- 同一密集区域内表达完整语义的图元合为一个编辑单元，颜色差异不构成拆分依据。
  - 例如，同一片多色散点及其内部连线共同表达样本分布，应整片合并。
  - 样本分布的选定区域最终对应一个叶对象，分组不能代替叶对象压缩。
- 选定密集区域能用单个复合路径忠实表达时，合为该路径；否则整片转为局部图片。
  - 同色图元可合为复合路径。
  - 多色散点可整片保留为局部图片。

密集区域按语义压缩后，图标还须按结构复杂度逐个裁决。

**图标裁决：**

- 简单图标转整体矢量，复杂图标保留局部位图。
- 每个图标在画布中只放置一个实例，禁止展开为大量小对象，也不能用分组代替对象压缩。

文本合并保留原生编辑能力，不通过图片替代文字。

**文本裁决：**

- 同一段落的多行合为一个文本框，标题与正文分别保留；标题附带的限定说明仍归标题，包括括号限定语。
- 同一模块、相邻位置或内容相关不足以跨单元合并。
- 合并为一个SVG `text`，用 `tspan` 保留位置与混合样式，导出为一个原生PPT文本框。
- 单元内部保留不同字号和粗细；分组或文字栅格化均不满足文本合并。

裁决结果写入显式计划，脚本只负责执行已确定的操作。

### 转换

`merge-plan.json` 记录选中元素及其语义理由。

转换保持详细源稿，所有后处理均在工作副本上进行，依次完成：

1. 用 `scripts/compact_svg.py` 执行适用计划；脚本不负责选择元素。
2. 超出支持范围时，在运行目录编写专用转换代码，遵守相同约束并检查局部渲染。
3. 对照压缩前后渲染，检查文字、色彩和连接关系，复查已记录缺陷。
4. 按 [导出参考](references/exporter.md) 写入 `ppt-object-plan.json`，用 `scripts/svg_to_pptx.mjs INPUT.svg OUTPUT.pptx --plan PLAN.json` 导出；脚本消费对象计划并生成结构报告与最终文件预览。

导出时分别处理普通组件、复杂资产与背景层级。

**对象要求：**

- 按 [原生对象选型](references/postprocess.md#原生对象选型) 使用预设形状与连接符；箭头使用原生端点。
  - 自由曲线不等于对应的预设形状，线条加三角形不等于原生连接箭头。
  - 按 [整体图标](references/postprocess.md#整体图标) 逐个选择矢量或位图；每个图标保留单个对象。
- 背景面板保留完整形状，局部色块作为独立对象置于上层，不得因遮挡而挖孔或切碎。
- 底层全画布纯色背景使用PPT页面背景，局部覆盖层保留为独立对象。
- 导出失败须修复具体组件，禁止用整页图片代替。

图标转换可复用上游抠图，输出类型仍取决于逐个裁决的结果。

**图标资产：**

- 上游抠图用于简单图标的矢量重建，也可作为复杂图标的交付资产。
- 记录每个图标的结构依据与输出类型，禁止将整批图标默认归为复杂图标。

对象结构正确后，还需从最终文件核对外观和编辑行为。

## 交付

渲染最终PPTX，与SVG及定稿生成图按相同画布尺寸叠加对照。

按字体替换规则检查文字，其余区域核对外观一致性，修复缺失或移位后再交付。

**文件检查：**

- 选定样本分布区域在SVG与PPT中均为一个叶对象；每个图标为一个整体对象，文本单元各为一个文本框。
- 核对完整文字与粗细样式，检查实际PPT对象类型及连接符绑定，移动模块验证箭头跟随。
- 检查PPTX实际文件，确保备注内容为空。
- 提供原始SVG、压缩SVG、PNG和PPTX链接，报告真实压缩数量及局部图片范围。

交付说明须区分已完成的结果和仍待处理的问题。

> **未完成判据**
>
> 全画布栅格、未处理的密集图元或无法运行的必要步骤均须标为未完成。
>
> 字体替换与明确缺陷修复之外的外观差异须如实记录，未解决时不宣称一比一复刻。
