# 可编辑转换

定稿图进入AutoFigure-Edit的SVG重建流程，主程序完成后再进行对象压缩和PPTX导出。

## SVG重建

AutoFigure-Edit依据定稿图完成分割与抠图，再生成SVG模板并替换图标，输出 `final.svg`。

上游阶段顺序与提示模板保持冻结，当前Agent检查主流程结果，在工作副本中处理后续转换。

> **外观依据**
>
> SVG和PPTX除字体替换与已记录的明确缺陷外，须一比一复刻定稿图。
>
> 原始 `final.svg` 保持不变，后处理只修改独立工作副本。

先对照定稿图检查SVG。整页图片形式的保底SVG按主流程未完成处理，定位日志错误后再继续。

### 局部修复

结合方法语义和图形连续性识别明确缺陷，含义不明的内容保留原意。

**修复步骤：**

1. 同时查看定稿图与SVG，核对方法中的真实连接关系。
   - 语义缺陷须与方法中的真实关系核对，例如多余箭头或错误分支。
   - 外观缺陷须结合可读性与图形连续性判断，例如文字遮挡、边框断裂或残留色块。
2. 在工作副本修复局部图形，记录位置、依据与结果。
   - 保留未涉及区域的语义与布局，维持图形层叠关系。
   - 背景面板保持完整，前景色块独立覆盖，遮挡区域按[背景规则](#背景)处理。
3. 按相同画布尺寸渲染并对照修复区域，记录检查结果。
   - 原稿与上游代码保留原样，其他区域维持定稿图外观。
   - 无法解释的差异须继续修正，未解决时标为未完成。

风格不符合要求时，返回[生图设计](design.md)调整输入并重新生图，再执行转换。

> **重建限制**
>
> 矢量重建须保留定稿图外观，不能借导出适配换色或改写文字，也不得简化轮廓或重新设计图标。

局部缺陷处理后，按下节确定编辑单元；图标类型及验证要求统一见[整体图标](#整体图标)。

## 对象裁决

Codex决定编辑单元，脚本执行选定操作；压缩以实际叶对象数量衡量，分组数量不能代替对象数量。

**工作副本：**

- 使用已核对缺陷的SVG工作副本与渲染图，定位密集细小图元。
- 给选中元素分配稳定ID，保存带ID的工作副本，原始 `final.svg` 保持原样。
- 检查层叠顺序、变换与透明度，记录每组对象的语义理由。

图形、文本和背景承担不同编辑职责，按各自边界处理。

### 图形

密集区域以用户会整体移动的最小完整对象为单位。

外部文字、面板和跨对象连线保持独立，合并时保留全部内部细节。

**合并方式：**

- 每个选定密集区域保留一个叶对象；单个复合路径能忠实表达时采用该路径，例如同色图元组成的完整区域。
- 单个复合路径无法忠实表达的密集区域整片转为图片，保留完整笔画。例如，多色散点云须包含内部连线。
- 编辑单元按完整语义划分，颜色分层仅用于中间处理。例如，同一片散点的不同颜色仍属于同一个对象。

密集样本分布按上述规则压缩，图标按下节的结构复杂度选择矢量或位图。

每个图标在画布中只放置一个实例，禁止拆成密集小对象。

### 整体图标

图标按结构复杂度逐个选择表示方式，每个图标只占一个可整体移动、缩放的对象。

简单图标转矢量；复杂图标保留局部位图，避免高成本描摹和密集小对象。

**分类依据：**

- 简单图标由少量矩形、圆或直线等基本图形组成，轮廓清楚，可用少量路径忠实表达。
- 复杂图标包含大量细节、不规则曲线或纹理，忠实矢量重建需密集描摹，优先保留原图。
- 复杂度按忠实重建所需的几何细节判断；颜色数量、文件大小或导出器限制不足以单独判为复杂。
- 每个图标记录ID、可见结构依据与输出类型，禁止整批默认保留位图；无需先穷尽转换才作裁决。

例如，简单立方体虽有立体外观，仍可由少量基本图形忠实表达，应归为简单图标。

分类决定资产格式，外部文字与流程箭头仍保留各自的原生编辑能力。

**封装方式：**

- 简单图标能用一个预设形状忠实表达时，PPT必须采用该类型；预设形状不匹配时再选复合路径。
- 预设形状无法忠实表达的简单多色图标封装为纯矢量SVG资产；总图嵌入一个image实例，PPT保留单个SVG图形。
- 复杂图标使用定稿图的局部位图，优先复用上游抠图；保留细节和清晰度，裁剪不损伤轮廓。
- 两类图标都禁止拆成密集小对象；分组不能代替单对象，标签与面板不能并入图标截图。

简单图标的SVG资产采用 `data:image/svg+xml;base64,...` 嵌入，资产内部禁止包含位图。

PPT矢量图形可带兼容预览，但须保留SVG资源及有效关联；复杂图标单独计为栅格图片。

**交付核验：**

- 核对每个图标的分类依据、资源类型与对象数量，SVG主画布和PPT中均只有一个实例。
- 简单图标检查矢量几何或SVG资源关联；复杂图标检查原图细节、透明边缘与裁剪范围。
- 矢量图标保留独立源文件，复杂图标保留原始局部图片；默认编辑粒度均为整个图标。
- 简单图标意外栅格化或任一图标展开为小对象时，须修复后交付，不能改分类掩盖导出问题。

图标规则不改变普通组件的原生对象要求，也不改变冻结的上游链路。

配套导出脚本尚未验证整体SVG资产的端到端保留，Agent须在运行目录适配并完成上述检查。

### 文本

文本按完整语义单元合并，保留原文内容与强调层级；字体可重新选择，无需匹配生成图的字形。

同一模块或位置相邻不构成跨单元合并的理由。

**合并边界：**

- 一个正文段落对应一个文本框，标题独立为另一个文本框。
- 同一语义单元的附属说明归入该单元，换行或标点不改变边界。例如，标题括号限定语归入标题，完整段落跨行仍合并。
- 不同字号与粗细通过SVG `tspan` 和PPT富文本保留。
- 分组或文字栅格化不满足语义文本合并，外部标签仍保持独立。

字体替换按语言选择，推荐字体及排版要求如下：

- 中文推荐微软雅黑或宋体；英文推荐Times New Roman或Comic Sans，同类文字保持一致。
- 选择执行环境可用且覆盖所需字符的字体，记录实际字体；推荐字体不可用时选清晰的替代字体并说明。
- 保留文字内容与层级，维持标签锚点及归属；仅因字体度量变化调整换行或基线，保持其在流程中的位置。
- 按实际渲染调整文本框与行距，必要时调整字号，避免截断或遮挡；保留数学符号含义与必要字重。

字体验收以清晰可读、内容完整及归属明确为准，字形与抗锯齿差异不计为复刻失败。

语义单元确定后，背景按遮挡关系保留完整几何形状。

### 背景

局部背景须保留完整几何形状，包括被遮挡区域；前景覆盖层保留独立对象，按原层级叠放。该规则适用于任意配色。

> **完整底层**
>
> 不得沿覆盖区域给底层挖孔、切碎底色或仅描摹可见边缘。
>
> 局部背景与覆盖层分别保留原生几何对象，不合成镂空路径或截图。

例如，绿色面板上的白色内容区应表示为完整绿底与独立白色覆盖层，绿底在遮挡区域仍保持连续。

整页页底另按PPT页面背景处理，转换条件见下文；局部覆盖层始终保留对象身份。

## 压缩执行

`merge-plan.json` 保存选中元素、操作类型及语义理由。

从仓库根目录执行命令，先设置本节使用的路径变量：

- `PROJECT_PYTHON` 设置为项目的 `.venv/bin/python` 绝对路径。
- `SKILL_DIR` 指向本Skill的绝对目录，`RUN` 指向本次运行目录。

脚本只执行显式计划，操作支持范围决定能否使用现成转换。

### 操作支持

配套脚本保留父级变换与局部坐标，支持范围如下。

不受支持的结构由Codex在运行目录编写专用转换，继续遵守相同编辑约束。

**可用操作：**

- `vector` 要求连续同父节点，支持 `circle`、`ellipse`、`line` 和以绝对 `M` 开头的 `path`。
- `raster` 仅支持一个根级 `group`，`bbox` 使用根坐标。
- `text` 将Codex选定的纯文本行合为一个 `text` 容器，保留逐行坐标与样式。

PPT文本导出另有版式支持条件，需在合并前核对。

**文本版式：**

- 配套导出支持共同横坐标、统一字体和等距行位置，允许字号与粗细不同。
- 不等行距或不同缩进的段落须专门转换，在同一原生文本框中保留段落格式并核对渲染。

版式差异不能成为拆分语义单元的理由，特殊结构须验证后交付。

### 合并计划

计划中的ID对应工作副本元素，`reason` 记录语义裁决依据。

下面示例将整片多色散点压为一个对象，并合并标题及限定说明。

```json
{
  "operations": [
    {
      "kind": "raster",
      "ids": ["multi-color-cloud"],
      "bbox": [100, 200, 300, 100],
      "name": "sample-cloud",
      "reason": "整片多色散点表达一个样本分布"
    },
    {
      "kind": "text",
      "ids": ["module-title", "module-subtitle"],
      "name": "module-label",
      "reason": "模块名称及其限定说明属于同一语义单元"
    }
  ]
}
```

将计划应用到带ID的工作副本，输出压缩SVG。

```bash
"$PROJECT_PYTHON" "$SKILL_DIR/scripts/compact_svg.py" \
  "$RUN/source-with-ids.svg" \
  "$RUN/merge-plan.json" \
  "$RUN/editable.svg"
```

执行结果需同时核对对象记录与实际渲染。

**压缩核验：**

- 检查 `editable.objects.json`，计数排除 `defs` 定义、分组容器和文字 `tspan`。
- 选定样本分布区域须为一个叶对象；图标各为一个整体对象，文本单元各为一个 `text`。
- 空计划仅适用于Codex已检查并确认没有密集对象的图。
- 跨父层或复杂样式的专用转换须保持外观；未验证的结构标为待解决，不能静默忽略。

压缩稿通过检查后，使用Artifact Tool生成PPTX。

## PPTX导出

先确定完整语义对象及目标PPT类型，再核对导出能力。选型记录完成后，才执行本节的转换命令。

### 原生对象选型

完整语义对象按图中用途确定，其边界由对象裁决决定。SVG的路径数量、分组或标签类型仅描述源稿结构。

> **语义类型必须匹配**
>
> PowerPoint的专用对象能表达所需外观和编辑行为时，必须使用该类型，禁止拆成基础形状拼接或改用自定义轮廓。
>
> 按完整对象验收。组成部件各自为原生形状、合成单个路径或加上分组，均不能代替正确的对象类型。

例如，矩形与三角形共同表达一支宽实心箭头时，须转换为一个预设块箭头，保留调整箭头比例的能力。

下表规定常见对象的目标类型，未列出的对象也遵循上述规则；实际表示方式还须满足图标及密集区域的专门约定。

| 图中内容 | 匹配时必须使用的PPT对象 | 编辑要求 |
| --- | --- | --- |
| 标题、正文或标签 | 文本框或形状内文本 | 可修改文字；保留语义单元及富文本 |
| 直线流程箭头 | 直线连接符及原生箭头端点 | 箭头与线身属于同一个连接符 |
| 直角折线连接（如采用该走线的残差支路） | 肘形连接符及原生箭头端点 | 保留硬折角，可调整端点与折线路径 |
| 整条弧形连线 | 能匹配原图的曲线连接符及原生箭头端点 | 核对曲率；不得给直角连线加圆弧 |
| 宽实心箭头 | 左右上下箭头、双向箭头等预设块箭头 | 用形状调整点控制箭头比例 |
| 面板及基础几何 | 矩形、椭圆、三角形、菱形、平行四边形等预设形状 | 保留尺寸与形状调整能力；圆形用等宽高椭圆 |
| 流程图节点 | 处理、判断、数据、文档等预设流程图形状 | 按节点含义选型，保持原图轮廓 |
| 容器及立体示意 | 圆柱、立方体等预设形状 | 保留透视与配色；独立着色的面无法由预设类型表达时，按特殊轮廓规则处理 |
| 弧线及标注符号 | 弧、括号、标注框等预设形状 | 保留可调参数，标签仍可编辑 |
| 表格 | 原生表格 | 可编辑单元格，禁止逐格拼矩形 |
| 有明确数据的统计图 | 原生图表及其数据 | 保留系列与数据编辑；示意柱条不得虚构数据 |
| 整页纯色底 | 页面背景 | 不产生可选中的全页矩形 |

预设形状、连接符和表格等具有各自的编辑行为，自由曲线只保留路径编辑能力。

图片或分组也各有用途，不能用一个可编辑对象总数代替类型检查。

对象类型须在导出前落实到逐对象记录，转换过程和最终验收共用这份记录。

#### 选型记录

在运行目录保存 `ppt-object-plan.json`，覆盖全部语义对象。它供Agent组织转换和核验，配套脚本不会自动读取该记录。

**记录内容：**

- 导出前记录对象ID及用途，列出对应SVG元素ID，明确完整语义对象的边界。
- 指定目标对象类型及预设名称，写明预期对象数量；连接关系记录起终点及对应模块。
- 采用特殊表示时记录适用规则和结构依据；图标及密集区域沿用对象裁决结果。
- 导出后补充幻灯片位置、实际PPT对象ID及类型，记录外观和编辑行为的核验结果。

同一对象可以对应多个SVG元素，转换后数量按语义要求确定。页面背景记录页面位置，不计为可选形状。

下表仅展示记录之间的对应关系，实际记录须使用本次图稿的ID和目标类型。

| 语义对象示例 | SVG来源示例 | 目标类型 | 预期结果 |
| --- | --- | --- | --- |
| 模块间流程箭头 | 线身路径及独立箭头头部 | 带原生端点的连接符 | 一个连接符，绑定所属模块 |
| 宽实心箭头 | 矩形及三角形 | 对应方向的预设块箭头 | 一个可调整比例的箭头形状 |

选型完成后，按箭头用途处理其对象类型和端点关系。

#### 箭头转换

线身与端点表达连接关系的箭头采用连接符；填充轮廓表达方向的箭头采用预设块箭头。源稿拆分方式不改变选型。

**转换规则：**

- 流程连线每条使用一个连接符，单向或双向箭头通过原生端点属性设置，线身与头部属于同一个对象。
- 宽实心箭头使用对应的预设块箭头，按原图调整方向与比例；禁止用独立几何部件拼成箭头。
- 连接模块的流程边须绑定模块连接点，移动模块后仍跟随；原图自由端点保持自由，并记录其依据。
- 分叉按真实起终点拆为多条连接符，共享节点保持重合，箭头标签独立保留。

端点按原图选择样式及尺寸，可用三角、开放式或Stealth等原生样式，也可用菱形与椭圆。

例如，曲线路径与独立三角形共同表达流程箭头，且曲率可匹配时，应恢复为整条带端点的连接符。

存在特殊轮廓时，先检查对应预设类型的可调参数，再判断是否需要例外表示。

#### 特殊轮廓

例外只针对预设类型确实无法表达的结构，不改变其余对象的选型要求。

**采用条件：**

- 记录最接近的预设类型、检查过的调整参数，以及仍无法表达的具体轮廓或分面配色。
- 几何差异有明确依据时，可使用必要的自定义路径或基本形状组合，保留完整语义及原有外观。
- 曲线路由超出连接符能力时，记录无法匹配的部分，保留自由曲线及原生箭头端点，并说明绑定能力的缺项。
- 导出器暂不支持、SVG原本使用路径或转换更省事，均不能作为例外依据。

例如，立体结构的各面独立着色而预设形状无法表达时，可用原生面片组合；此项不豁免完整图标的单对象要求。

外观复刻与对象类型均须满足。两者无法同时完成时，记录具体未完成项，禁止无记录地降级后宣称通过。

几何选型确定后，导出工具须实现这些选择；工具能力不足按下一节补齐。

#### 导出能力

`scripts/svg_to_pptx.mjs` 将SVG的line导出为普通线条，其余基础几何与路径多为自定义形状。

脚本拒绝marker，尚不生成连接符、原生箭头端点或绑定，执行成功不能代表类型验收通过。

Agent按选型记录补齐当次运行所需能力，依次执行：

1. 核对每个目标类型能否由当前工具生成，标记需要补充转换的对象。
2. 用已验证的Artifact Tool能力或PPTX结构转换实现目标类型，专用转换保存在运行目录。
3. 执行转换并补全实际对象ID，移除已替代的旧部件，保留原始SVG。
4. 按对象检查与视觉验收逐项核对，未完成的必要类型继续修复或如实标为未完成。

例如，生成预设箭头后，原有线身与头部部件须从PPT中移除，避免叠放掩盖重复对象。

转换方案确定后，先处理SVG样式和资源，再执行导出。

### 组件处理

文字、基础几何与连接线必须转换为原生PPT对象。

图标按整体图标规则选择表示方式，简单图标转矢量，复杂图标保留原图局部位图。

**兼容处理：**

- 将CSS样式内联为显式属性，清除已解析的 `class` 和 `style` 规则。
- 已拆分的箭头先恢复完整语义，再按用途转换为连接符或预设块箭头，遵循箭头转换规则。
- 逐个按分类结果处理图标，保留原图外观；导出失败须修复具体问题，不能将简单图标改判为复杂。
- 特殊轮廓需自由曲线时才采用路径采样；偏差超过1像素须修正，预设弧形与连接符优先。

背景转换取决于对象所在层级，不能仅按颜色决定是否删除。

**背景对象：**

- 底层全画布、无描边无圆角的不透明纯色矩形转换为PPT页面背景。
- 局部覆盖层按层级与几何形状保留独立原生对象，填色和边框不改变其身份。例如，纯白覆盖层仍保留为对象。

组件准备完成后，加载运行时并执行转换。

### 运行时

运行时路径由Codex桌面的 `load_workspace_dependencies` 查询，远端按教程使用已部署路径。

读取当前环境的Presentations Skill，准备产物目录和运行标记。将运行时信息写入以下环境变量：

- `RUNTIME_NODE` 指向返回的Node可执行文件。
- `RUNTIME_NODE_MODULES` 指向返回的包目录。
- `ARTIFACT_TOOL_PATH` 指向包内 `@oai/artifact-tool/dist/artifact_tool.mjs`。

环境变量就绪后，按选型记录执行已确定的导出方案。以下命令可生成基础PPTX，其结果仍须完成类型修复与验收。

```bash
"$RUNTIME_NODE" "$SKILL_DIR/scripts/svg_to_pptx.mjs" \
  "$RUN/editable.svg" "$RUN/final.pptx"
```

导出错误须定位到具体元素，再按对象职责处理。配套脚本无法承载的目标类型，由前述专用转换完成。

最终对象对应关系写回选型记录，再检查实际PPTX包内结构。

### 对象检查

最终PPTX须保留语义编辑单元和原有层叠关系。

分别统计文本框、连接符及预设形状；自由曲线与图片另计，分组内部对象同样纳入统计。

> **备注为空**
>
> 检查实际PPTX包内备注，确保没有演讲者备注或其他备注文字。

逐项读取选型记录，并核对最终PPTX中的真实对象；记录中的类型名称不能代替文件证据。

**对应核验：**

- 从每个语义对象定位到对应幻灯片及PPT对象ID，核对数量与层级，禁止仅按全页对象总数判断。
- 反查PPT中的可见对象，确认均有归属，旧部件已移除，独立标签仍保留。
- 检查分组内部对象和重叠对象，分组、隐藏或覆盖均不能掩盖不合格的替代部件。
- 特殊表示逐项核对依据及能力缺项，所有未完成项保留状态，不能计入通过数量。

对象对应完整后，检查每项应具备的PPT结构，并在检查副本中验证编辑行为。

**类型验收：**

- 流程连线检查 `p:cxnSp`，核对路由及端点属性；连接模块的端点另检查绑定。
  - 箭头检查 `a:headEnd` 或 `a:tailEnd`，箭头端的 `type` 必须非 `none`，并核对方向与尺寸。
  - 检查 `stCxn` / `endCxn` 指向的模块和连接点，移动模块验证跟随；自由端点按记录核对。
- 预设形状检查 `a:prstGeom` 的具体类型与调整参数，须与选型一致；单有该节点不算通过。
- 表格与图表检查专用对象结构及可编辑内容，图片与分组不得计为对应原生类型。
- 自定义几何及其他特殊表示逐项检查适用规则和结构依据；曲线路由例外仍须验证原生箭头端点。

例如，宽实心箭头应是对应的块箭头预设；即使矩形与三角形都含预设几何节点，拼接结果仍判为不合格。

> **交付判据**
>
> 对象对应完整、类型匹配、外观一致且所需编辑行为已验证，才可报告通过。
>
> 缺少证据、错误类型或未解决的能力缺项均标为未完成。渲染相似、脚本成功或对象数量减少不能代替验收。

未运行交互检查时，明确保留该项未验证状态；特殊表示的能力缺项同样如实交付。

对象类型通过检查后，继续核对对象边界和背景层级。

**编辑检查：**

- 每个选定样本分布区域对应一个shape或picture，每个图标对应一个整体对象。
- 每个文本单元对应一个含完整文本的shape，保留混合字号、粗细与换行。
- 在检查副本中隐藏或移开覆盖层，确认下方背景连续、完整且无镂空。
- 恢复覆盖层，核对背景与覆盖对象的独立性、层叠顺序及外观。

图标验收须对照分类记录查看实际元素，不能仅凭文件扩展名判定矢量或位图。

**图标验收：**

- 简单图标须为单个矢量对象，复杂图标须为单个局部位图；分组后的密集子对象不算完成。
- 图标与密集散点分别记录依据，禁止用重命名或整批分类绕过简单图标矢量化。
- 输出类型与分类不符或外观失真时标为未完成，继续处理具体组件。

结构核验完成后，还需按最终渲染判断视觉一致性。

## 视觉验收

定稿生成图是图形外观依据，缺陷修复须记录具体区域；字体按[文本规则](#文本)替换并核验。

原稿SVG、压缩SVG和最终PPTX均按相同画布尺寸与定稿图叠加对照。

先将压缩稿渲染为PNG，便于检查合并前后的外观。

```bash
"$PROJECT_PYTHON" -m cairosvg "$RUN/editable.svg" -o "$RUN/editable.png"
```

原稿使用相同工具另存为 `original.png`，两份渲染共同作为对照材料。

```bash
"$PROJECT_PYTHON" -m cairosvg "$RUN/final.svg" -o "$RUN/original.png"
```

导出器的预览与最终PPTX分别检查，避免只验证导出前状态。

**渲染检查：**

- 查看导出器生成的 `final.pptx.preview.png`。
- 按Presentations Skill用 `render_presentation.mjs` 重新导入PPTX并渲染。
- 文字按字体替换规则核验；图形核对连线端点、图标与色彩，明确缺陷修复之外须一比一复刻。
- 预览能生成不等于视觉合格，须人工查看并修复缺失或移位。

通过验收的文件连同真实检查结果一起交付。

**交付内容：**

- 提供 `final.svg` 原稿与 `editable.svg` 压缩稿，附PNG和 `final.pptx`。
- 提供逐对象选型及核验记录，列明通过、未验证与未完成项，特殊表示保留依据和能力缺项。
- 报告各区域压缩数量、局部图片范围与实际完成的检查，保留输入材料、启动命令和运行日志。
